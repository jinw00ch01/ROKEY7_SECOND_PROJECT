# 2026-05-12 인식 dedup·클러스터 판정 개선 + TTS/툴 정리

`main` 브랜치에서 작업한 라이브 시스템 튜닝 모음. 운영 중 발견된 세 가지 이슈를 처리했다.

- 봇이 모든 응답에 "샤갈!" 접두어를 붙여 말함 → 호출어는 유지하고 TTS 인사말만 제거.
- 트리거 기반 OD 디버그 뷰어(`yolo_rqt_view.py`)가 cyclonedds 환경에서 카메라 프레임을 못 받음 → QoS RELIABLE로 강제.
- 군집(cluster) 판정과 다중 프레임 dedup 모두 견과 크기를 무시한 단일 임계값을 사용 → cluster는 edge-to-edge gap, dedup은 클래스별 임계값으로 분리.

## 1. TTS "샤갈!" 인사말 제거

### Why

봇이 모든 응답 메시지 앞에 "샤갈!"을 강제로 prefix해서 운영 중 불필요하게 들렸다. 호출어로서의 "샤갈"(사용자가 부르면 깨어남)은 그대로 두되, 봇이 **말하는** 쪽만 제거.

### What

| 파일 | 변경 |
|---|---|
| `cobot_voice/config/question_flow.json` | `wake_response` / `ask_job` / `ask_satiety` / `confirm_template` 4개 메시지에서 "샤갈! " prefix 제거 |
| `web_stt_supabase_v2/public/config/question_flow.json` | 동일 (웹 사본) |
| `web_stt_firebase_v2/public/config/question_flow.json` | 동일 (웹 사본) |
| `cobot_voice/cobot_voice/voice_order_flow.py:451, 496` | f-string의 하드코딩 `"샤갈! "` 제거 |

`voice_order_flow.py:405, 450, 495`의 `.replace("샤갈! ", "")` 호출은 JSON에서 이미 제거됐으므로 no-op이 되었지만 방어 코드로 잔존.

### 보존된 것

`web_stt_*_v2/src/lib/voice/wakeWord.ts`의 호출어 목록(`"hello rokey", "헬로 로키", "샤갈"`)은 미변경. 사용자가 "샤갈" 하고 부르면 봇은 여전히 깨어난다.

## 2. `scripts/yolo_rqt_view.py` QoS 수정

### Why

rqt에서 YOLO 추론 결과를 시각화하려고 standalone 뷰어를 띄웠는데 `/yolo/annotated`가 텅 빔. 원인은 cyclonedds 환경에서 BEST_EFFORT 단독 subscriber가 RELIABLE publisher로부터 메시지를 못 받는 알려진 패턴. 프로덕션 `object_detection_node.py:90-93` 주석에 이미 같은 워닝이 있다.

### What

| 파일 | 변경 |
|---|---|
| `scripts/yolo_rqt_view.py:38` | `ReliabilityPolicy.BEST_EFFORT` → `ReliabilityPolicy.RELIABLE` |

이후 `python3 src/cobot2/scripts/yolo_rqt_view.py` + `ros2 run rqt_image_view rqt_image_view /yolo/annotated`로 정상 표출 확인.

## 3. 군집 판정 공식 변경 — center-distance → edge-to-edge gap

### Why

`cluster_policy.choose_cluster_plan`이 대상-이웃 중심 거리만 보고 군집을 판정했다. 결과적으로 견과 크기가 다른 케이스에서 의미가 달라졌다.

- 작은 캐슈 두 알이 중심거리 18mm → 임계 15mm 초과 → 군집 아님. (실제로는 살짝 닿음)
- 큰 호두 두 알이 중심거리 25mm → 임계 15mm 초과 → 군집 아님. (실제로는 거의 붙어있음)

물리적으로 일관된 의미("표면 사이 간격")로 바꿔야 견과 크기에 무관한 튜닝이 가능하다.

### What

| 파일 | 변경 |
|---|---|
| `cobot_task_manager/cobot_task_manager/cluster_policy.py` | 판정 조건을 `dist < threshold` → `gap < threshold`로 변경. `gap = dist - r_target - r_neighbor`이고 각 r은 OBB를 target↔neighbor 연결선 방향에 SAT 투영한 half-width. 신규 헬퍼 `_projected_half_extent` 추가. 모듈 docstring 갱신. |
| `cobot_task_manager/config/task_manager.yaml` | 같은 파라미터 이름(`cluster_dist_threshold_mm`) 유지, 의미만 gap 기준으로 재해석. 주석 갱신. 값은 운영 튜닝으로 13.0mm로 조정. |

### Why "방법 1" (의미만 재해석)을 선택했나

- 새 파라미터 추가하면 yaml/노드 양쪽 동기화 부담.
- 사용처가 `cluster_policy.choose_cluster_plan` 한 곳뿐이라 의미 변경의 영향 범위가 좁음.
- 같은 변수명을 유지하면 launch override / 운영 스크립트 깨지지 않음.

호환성 트레이드오프: yaml에서 옛 값을 그대로 가져온 사용자는 동작 의미가 달라진다는 점을 인지해야 함. 주석에 명시.

### 검증

`python3 -m py_compile cluster_policy.py` 통과. 노드 재시작 후 군집 push가 의도대로 발동/억제되는지는 실측으로 확인 필요.

## 4. Per-class detection-dedup 임계값 — `dedup_thresholds.yaml` 도입

### Why

`detection_postprocess.DetectionAggregator`가 같은 클래스의 검출을 중심거리 `cluster_distance_threshold_px`(단일 글로벌 30px)로만 묶었다. 운영 중 그리퍼 아래 특정 구역에서 **두 아몬드가 한 개로 인식되는** 증상 보고. 다른 구역으로 옮기면 정상.

원인: 견과 크기에 무관한 단일 30px 임계는 슬림한 아몬드(픽셀 long axis ~25-35px)에는 과대하다. 두 아몬드가 거의 닿을 정도로 가까우면 중심거리 30px 이내 → 다중 프레임 윈도우(0.5초) 동안 평균 중심이 사이로 끌려가며 잘못 융합됨(chaining 가능).

견과류별로 분리된 임계값을 설정할 수 있어야 한다. `pick_offsets.yaml` 패턴이 이미 코드베이스에 검증돼 있어 동일하게 적용.

### What — 신규 파일

| 파일 | 역할 |
|---|---|
| `cobot_config/config/dedup_thresholds.yaml` | 견과별 픽셀 임계값. 초기값: almond 20, cashew 25, pistachio 20, walnut 30 (운영 튜닝 진행 중) |
| `cobot_object_detection/cobot_object_detection/dedup_thresholds.py` | 4단계 fallback resolver(`explicit_path → COBOT_DEDUP_THRESHOLDS_PATH → ament-share → 소스 트리`). `load_dedup_thresholds()` 반환 = `Dict[str, float]`. 누락 키는 `fallback_px`로 채움. `pick_offsets.py` 구조를 그대로 미러 |

### What — 수정 파일

| 파일 | 변경 |
|---|---|
| `cobot_object_detection/cobot_object_detection/detection_postprocess.py` | `DetectionAggregator.__init__`이 `cluster_distance_px: Union[float, Mapping[str, float]]` 받도록 확장. 내부적으로 `_cluster_dist_by_class` dict + `_cluster_dist_fallback` float로 정규화. `_threshold_for(class_name)` 헬퍼 추가. `fuse()`의 inner loop가 클래스별 임계를 lookup해 비교. float 입력은 그대로 동작 (back-compat). |
| `cobot_object_detection/cobot_object_detection/object_detection_node.py` | `dedup_thresholds_path: ""` 파라미터 추가. `load_dedup_thresholds()`로 dict 로드, aggregator에 전달. 시작 로그에 `Dedup thresholds (px): {...}` 1줄 추가. |
| `cobot_perception/cobot_perception/perception_transform_node.py` | 동일 변경. `self._aggregator_cluster_px`가 float → dict로 타입 변화. `_capture_and_infer()`에서 매번 새 `DetectionAggregator` 생성하는 기존 패턴 그대로 (dict는 매번 그대로 전달됨). |
| `cobot_object_detection/config/object_detection.yaml` | `dedup_thresholds_path: ""` 추가. 기존 `cluster_distance_threshold_px: 30.0`은 **legacy fallback**으로 유지(누락 클래스용). 주석 갱신. |
| `cobot_perception/config/perception.yaml` | 동일. |
| `cobot_object_detection/package.xml` | `<exec_depend>cobot_config</exec_depend>`, `<exec_depend>python3-yaml</exec_depend>` 추가 (런타임에 yaml 로드 의존성). |
| `cobot_perception/package.xml` | 동일. |

### 설계 선택 이유

- **별도 yaml(옵션 B)** — 코드베이스에 `pick_offsets.yaml` 선례 있음. 단일 파일에 인라인 dict 박는 것보다 SoT 분리·재사용·외부 도구로 편집 용이.
- **float/dict 양수형 aggregator** — 기존 callers(테스트 / 외부 스크립트)가 깨지지 않도록 back-compat 유지.
- **dict 우선 + single-value fallback** — `cluster_distance_threshold_px` legacy 파라미터를 제거하지 않고 fallback으로 남김. 신규 클래스가 yaml에 빠져 있어도 노드는 동작.
- **로더는 `cobot_object_detection`에 둠** — `cobot_perception`도 같은 aggregator를 import해 쓰므로 두 노드가 공통 모듈을 공유. 대안(`cobot_config`에 python 모듈)은 cobot_config가 CMake 패키지라 부적합.

### 검증

```text
$ python3 -c "from cobot_object_detection.dedup_thresholds import load_dedup_thresholds; print(load_dedup_thresholds())"
Loaded: {'almond': 20.0, 'cashew': 25.0, 'pistachio': 20.0, 'walnut': 30.0}
```

`DetectionAggregator` 단위 시나리오:
- 18px 떨어진 두 아몬드(임계 20px) → **1개로 융합** (기대됨, 임계 줄여 18→15 등으로 추가 튜닝 시 2개로 분리).
- 20px 떨어진 두 호두(임계 30px) → **1개로 융합** (같은 너트의 다중 프레임 융합).
- float-only 입력 → 기존 동작 그대로 (back-compat OK).

## 5. 운영 메모

### 새 yaml 위치 우선순위

1. ROS 파라미터 `dedup_thresholds_path` 명시 (launch override 가능).
2. 환경 변수 `COBOT_DEDUP_THRESHOLDS_PATH` (운영 중 임시 덮어쓰기).
3. ament-share `cobot_config/share/.../dedup_thresholds.yaml` (정상 install).
4. 소스 트리 `src/cobot2/cobot_config/config/dedup_thresholds.yaml` (dev fallback).

### 임계값 튜닝 가이드

| 견과 | 픽셀 long axis (관찰값 범위) | 초기 임계 | 메모 |
|---|---|---|---|
| almond | 25-35px | 20.0 | 슬림해서 인접 시 false-merge 잘 일어남. 필요 시 15~18로 더 좁힘 |
| cashew | 30-40px | 25.0 | 초승달이라 OBB 흔들림 큼. 너무 좁히면 같은 너트가 2개로 분리됨 |
| pistachio | 20-30px | 20.0 | 작고 둥금. 아몬드와 비슷한 트레이드오프 |
| walnut | 35-50px | 30.0 | 큰 너트는 같은 인스턴스도 OBB가 크게 흔들려 넓은 임계가 안전 |

`object_detection_node`와 `perception_transform_node` 둘 다 같은 yaml을 읽으므로 한 곳만 수정하면 양쪽 반영.
