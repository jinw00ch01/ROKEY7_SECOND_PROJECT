# 2026-05-11 Supabase 마이그레이션 통합

`feat/supabase-migration` 브랜치에서 작업한 전체 변경분이 `main`으로 머지된 시점의 기록. 새 백엔드 경로(`Supabase`)와 기존 경로(`Firestore`)가 launch 인자 토글로 공존한다.

## 1. 배경 (Why)

원래 `cobot2`는 두 가지 영속화 요구를 가졌다.

- **실시간 세션 동기화** — 음성 STT 흐름이 작성하는 주문/상태/테마를 웹 UI가 실시간 구독. Firestore가 잘 맞았음.
- **이력/재고 관리** — 픽 성공/실패 로그, 재고 차감/리필, 예외 분류. SQL이 더 자연스러움.

초기 의도는 "실시간은 Firebase, 이력/재고는 Supabase"였으나, 두 백엔드 동시 운용은 자격증명/RLS/네트워크 의존 표면을 두 배로 만들어 데모 운영 부담이 컸다. 그래서 Supabase 하나로 통일한 경로를 추가하되, 즉시 롤백 가능하도록 Firebase 경로도 launch 토글로 공존시킨다.

자세한 설명은 `docs/09_supabase_migration.md` 참조.

## 3. 데이터 모델 핵심 결정

1. **단일 행 운영**: `robot_session.id = 'current'` CHECK 제약으로 다른 ID를 차단. Firestore `robot_session/current` 문서와 1:1.
2. **재고 차감은 RPC만**: 클라이언트 측 `UPDATE current_stock = current_stock - 1`은 race 위험. `update_inventory_atomic(SECURITY DEFINER)`이 UPDATE + INSERT (inventory_logs)를 단일 트랜잭션으로 처리. RLS는 anon SELECT만 허용, 쓰기는 RPC 경유 강제.
3. **`task_name` CHECK**: exception_logs는 `'cluster_push'` 또는 `'verification_round'`만 허용. 의도적인 마찰 — 새 종류 추가 시 SQL + `_VALID_TASKS` 양쪽 갱신.
4. **`reason`에 phase 인코딩**: `inventory_logs.reason`을 `primary_pick_success` / `verify_pick_success_round_N`으로 라벨링하여 시계열 분석 시 어느 라운드의 차감인지 구분.
5. **`updated_at` 트리거**: Firestore `serverTimestamp()` 대체로 `BEFORE UPDATE` 트리거 `touch_updated_at`이 server-side로 처리.

## 4. 운영 함정 (사후)

마이그레이션 적용 중 실제로 막혔던 지점들:

| 증상 | 원인 |
|---|---|
| 브라우저 검은 화면 | `.env`에 `VITE_` prefix 누락 → `supabase.ts`가 모듈 import 시점에 throw |
| `Invalid API key` | 키 placeholder `sb_publishable_REPLACE_ME` 그대로 |
| `supabase publish failed: SUPABASE_URL must be set` | 노드 CWD에 `.env` 없음 + `db_env_path` 빈 문자열 → `bringup_supabase.launch.py`가 `.env`를 직접 파싱해 SetEnvironmentVariable로 주입하도록 해결 |
| 색깔이 첫 견과류에 고정 | normalizer가 `robot_target_class` 누락 → `4a5b322`로 수정 |

전체 함정 목록은 `docs/09_supabase_migration.md §10` 참조.

```bash
alias bringup_supabase='ros2 launch cobot_bringup bringup_supabase.launch.py \
    task_autostart:=false enable_realsense:=false enable_dsr_bringup:=false \
    dsr_mode:=real config_robot_control:=$(ros2 pkg prefix cobot_robot_control)/share/cobot_robot_control/config/robot_control.real.yaml'
```

기존 `bringup`(firebase + firestore)은 그대로 두고 병행.
