### 3. TCP service timeout 및 worker 수 조정 (robot_control)

#### 진단
- Doosan `/dsr01/system/get_current_pose` 직접 호출은 **0.3~0.7ms** (정상)
- robot_control의 `/robot/get_current_pose` passthrough는 ~2s 소요
- 원인: `robot_pose_helper`의 `MultiThreadedExecutor(num_threads=2)`에서 핸들러가 ReentrantCallbackGroup으로 2번 동시 dispatch될 때, 두 핸들러가 polling으로 워커 모두 점유해 Doosan 응답 dispatch가 ~2s 지연

#### `cobot_robot_control/cobot_robot_control/robot_control_node.py`

```diff
-        # MultiThreaded with >= 2 workers: ...
-        self._pose_executor = MultiThreadedExecutor(num_threads=2)
+        # MultiThreaded with >= 4 workers: 동일 service request가 ReentrantCallbackGroup에서
+        # 병렬로 dispatch되어 핸들러가 동시에 polling 중인 케이스가 관찰됨. 워커가 2개만
+        # 있으면 양쪽 핸들러가 sleep+poll로 워커를 점유해 Doosan 응답 dispatch가 늦어진다.
+        # 4로 둬서 동시 핸들러 2개 + 응답 dispatch + 여유 1로 dead-lock-free 유지.
+        self._pose_executor = MultiThreadedExecutor(num_threads=4)
```

#### `cobot_robot_control/config/robot_control.real.yaml`

```diff

+    # Doosan get_current_posx가 가끔 ~2s 걸려 perception 측 timeout과 경합한다.
+    # robot_control은 그보다 짧으면 안 되므로 4s로 둔다.
+    pose_passthrough_timeout_sec: 4.0
```

#### `cobot_perception/config/perception.yaml`

### 5. perception_transform_node 트리거식 재설계 (대규모 변경)

#### 동기
- 첫 픽은 정상이지만 픽 2~4가 X≈394로 쏠리는 패턴
- TCP 회전(`posx[3]`)이 매 home마다 56° → 116° → 53°로 다름
- stream cache 기반: `_detection`(과거 frame의 픽셀) + `_current_tcp()`(NOW의 TCP) 조합 → frame 캡처 시점과 TCP 조회 시점이 다른 robot pose면 변환 불일치
- 즉 **structural timing bug**. delay 늘림으로는 근본 해결 불가

#### 새 아키텍처

```
[Before]                           [After]
realsense ─┬─ color                realsense ─┬─ color ───┐
           ├─ aligned_depth                   ├─ depth ───┤
           └─ camera_info                     └─ info ────┤
                                                          ▼
object_detection_node              perception_transform_node
  (30Hz YOLO 추론)                    (YOLO 내장, trigger-only)
       ↓                               ▲
  /detection/objects ───────────────/perception/detect_once
       ↓
perception_transform_node            [트리거 시:
  (cached frames 사용)                 1. fresh color frame N장 대기
                                        2. YOLO 추론 + DetectionAggregator fuse
                                        3. depth/info/TCP 동시 스냅샷
                                        4. 변환 → 반환]
```

## 미해결 / 후속 과제

### A. src ↔ install 불일치 (cobot_task_manager)
- src `cobot_task_manager/cobot_task_manager/task_manager_node.py` 484줄 (구버전)
- install 사본 648줄 (scatter / verification 로직 포함, 신버전)
- install yaml에는 scatter 파라미터 있으나 src yaml에는 없음
- 현재 `colcon build` 시 install 신버전 기능이 사라짐 → 본 세션에서는 build 회피
- 해결책: src를 install 신버전으로 동기화하거나, 신버전이 머지되지 않은 브랜치를 머지

### B. `[pose] handler entered` 2회 발생 패턴
- 원인 미상 (rclpy/cyclonedds discovery probe 가능성)
- num_threads=4로 워커 늘려 영향 차단했으나 호출 자체가 중복되는 점은 해결 안 됨
- 현재 동작에 영향 없음 (응답이 1ms 안에 처리되므로)

### C. verify round counting noise
- YOLO 검출이 noise로 1~2개 over/under count → verification 공식 `remaining = ordered - (initial - final)`이 부정확한 경우 발생
- 트리거식 재설계로 frame 안정성이 높아지면 자연 완화 예상
- 추가 안정화 필요시 `num_capture_frames` 상향 (5 → 10) 검토

### D. realsense USB 안정성
- 본 세션 중 두 차례 depth 스트림이 0Hz로 떨어지는 현상 관찰
- 색 스트림도 30Hz → 4Hz로 저하되는 시점 일치 → USB 3.2 대역폭 한계 가능성
- 카메라 power cycle (USB 재연결) 또는 realsense 노드 재기동으로 복구
