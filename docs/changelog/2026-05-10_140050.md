# 2026-05-10 web_stt_firebase v2 (브라우저 음성 → 로봇)

`voice-alias` (Python `voice_to_robot.py`)와 동등한 흐름을 **브라우저에서 직접**
실행하도록 v2 웹 앱을 신설하고, 로봇 dispatch까지 한 사이클을 연결한 작업 기록.

직전 커밋 `9d90566 docs: add perception/verification/cluster reports and session changelog` 기준.

## 1. 배경 (Why)

기존 `web_stt_firebase` (v1)는 Firestore의 `robot_session/current` 문서를
읽어 표시만 하는 React/Three.js 디스플레이였다. 마이크 캡처 → STT → 추천 →
TTS → Firestore write는 모두 Python (`cobot_voice/voice_order_flow.py` +
`web_voice_bridge_server.py`)이 담당했고, 브라우저는 이 Python HTTP bridge를
`http://127.0.0.1:8765`로 호출하는 얇은 트리거였다.

v2의 목표는 **Python voice bridge를 거치지 않고 브라우저가 직접** 음성 흐름을
끝까지 돌리는 것. STT(OpenAI Whisper)와 TTS(ElevenLabs)는 외부 API라 그대로
유지하고, 그 사이 wake word / state machine / 추천 로직 / Firestore 쓰기는
TS로 포팅한다.

세션 중간에 발견된 후속 문제 — TTS/STT는 잘 동작하는데 **로봇이 안 움직이는**
원인은 `voice_to_robot.py`가 추천 성공 시 `dispatch_to_task_manager()` →
`ros2 service call /task/start`까지 했던 것을 v2에서 누락해서. 브라우저는
`ros2 service call`을 직접 못 하므로 `rosbridge_websocket` + `roslib.js`로
서비스 호출을 우회한다. 추가로 `cobot_task_manager`가 v1의 `latest_order.json`
파일을 계속 읽고 있어 같은 `request_id`로 거부되는 문제도 같이 해결.

## 3. v2 웹 앱 (web_stt_firebase_v2)

### 3.1 디렉터리 구조

```
web_stt_firebase_v2/
  public/config/        cobot_voice/config/*.json 복사 (브라우저 fetch용)
  src/
    hooks/
      useVoiceOrchestrator.ts    음성 세션 시작/중단 hook (← useBrowserVoiceCommand 대체)
    lib/voice/
      orchestrator.ts            run_recommendation_flow() TS 포팅 (state machine 본체)
      recorder.ts                MediaRecorder 5초 캡처
      whisper.ts                 OpenAI Whisper transcriptions API
      tts.ts                     ElevenLabs TTS + 브라우저 재생
      wakeWord.ts                Web Speech API 기반 wake word 감지 (※)
      llm.ts                     gpt-4o State/Intensity 분석 + 메뉴 매칭
      recommendation.ts          extract_categories / extract_intensity / build_combo
      session.ts                 Firestore 세션 write (display_state, theme, order)
      questionFlow.ts            question_flow.json 로더
      rosbridge.ts               /task/start (Trigger) 호출 over rosbridge
  .env.local.example
  .env.local                     (gitignored: *.local)
```

(※) Python의 `openwakeword` (`hello_rokey_8332_32.tflite`)는 mel-spectrogram +
embedding + keyword 세 단계의 TFLite 모델 + JS inference runtime이 필요해서
이번 패스에서는 보류. 대신 Chrome/Edge `webkitSpeechRecognition` continuous
모드로 "hello rokey" / "샤갈" 키워드를 매칭. Firefox/Safari는 미지원이라
취소될 때까지 노옵.

### 3.2 음성 흐름 (orchestrator.ts ↔ Python `voice_order_flow.py`)

```
resetSession()
  → wake word 대기              [listenForWakeWord]
  → publishQuestion(wake_response, "wake_detected") + speak
  → publishQuestion(ask_state,    "asking_state")   + speak
  → updateDisplayState("listening_state")
  → recordAudio(5s) → Whisper STT → publishTranscript
  → analyzeState (gpt-4o) 또는 menu match
  → updateDisplayState("asking_intensity", theme=...)
  → publishQuestion(ask_intensity, "asking_intensity") + speak
  → updateDisplayState("listening_intensity")
  → recordAudio(5s) → Whisper STT → publishTranscript
  → analyzeIntensity (gpt-4o) 또는 menu match
  → updateDisplayState("recommending")
  → buildCombo(categories, intensity) → publishRecommendationResult
  → speak(confirm)
  → onDispatch(order):
       publishDispatching → /task/start 호출 → publishCompleted
```

각 단계의 Firestore 필드 의미는 `firebase_bridge.py`와 1:1.

### 3.3 환경변수 (Vite)

브라우저 번들에 들어가므로 **로컬/데모 한정**. 운영 배포 시에는 서버사이드 proxy 필요.

| 변수 | 용도 |
|---|---|
| `VITE_OPENAI_API_KEY` | Whisper + gpt-4o |
| `VITE_ELEVENLABS_API_KEY` | TTS (없으면 silent skip) |
| `VITE_PROMPT_MODE` | `freeform` (default) / `menu` |
| `VITE_TTS_ENABLED` | `0` 이면 TTS 비활성 |
| `VITE_ROSBRIDGE_URL` | `ws://localhost:9090` — 비어 있으면 dispatch 안 함 |

`.env.local`은 `cobot_voice/resource/.env`에서 OpenAI/ElevenLabs 키를 가져와 자동
스캐폴딩 (mode 0600). 키 자체는 changelog에 남기지 않음.

## 4. cobot_task_manager에 firestore order source 추가

### 4.1 왜 file이 아니라 firestore인가

기존 흐름:
- `voice_to_robot.py` → `save_recommendation_order(...)` → `latest_order.json` (`request_id` 갱신) → `/task/start`
- `FileOrderProvider`가 `latest_order.json` 읽고 `request_id` dedup

브라우저는 로컬 파일 쓰기가 불가능하다. 그러므로 v2에서 `/task/start` 만 호출하면
`task_manager`는 직전 Python 세션이 남긴 stale `request_id`를 보고
`order request_id ... already processed` 로 거부한다(실제로 첫 시도에서 그렇게 떨어졌다).

세 가지 옵션을 비교:
1. **`FirestoreOrderProvider` 신설** — task_manager가 `robot_session/current`에서 직접
   읽음. mock|db|file 패턴과 일관. ← 채택
2. 작은 Python adapter가 Firestore 구독 → `latest_order.json` write
   "Python bridge를 없앤다"는 v2 취지에 역행.
3. `/task/start`를 custom srv로 바꿔 order를 service request에 실어 보냄
   `cobot_msgs` 변경 + task_manager 리팩터 필요. 가장 침습적.

### 4.2 FirestoreOrderProvider 동작

`cobot_task_manager/cobot_task_manager/order_provider.py`:

- 지연 import (`firebase_admin`이 없는 환경에서 모듈 import 자체는 실패하지 않음)
- 인증: 생성자의 `service_account_path` → 빈 값이면 `FIREBASE_SERVICE_ACCOUNT` env →
  마지막으로 ADC (`GOOGLE_APPLICATION_CREDENTIALS` / metadata).
- `success=False` 거부 + `request_id` dedup: `FileOrderProvider`와 동일한 가드
- `combo` (list of `{nut, count}`)를 `{nut → count}` dict로 환산 후 `OrderBook` 반환

### 4.3 task_manager_node 파라미터

```yaml
order_source: "firestore"            # mock | db | file | firestore
firestore_collection: "robot_session"
firestore_document: "current"
firestore_service_account_path: ""   # 비우면 env 폴백
firestore_require_success: true
```

## 5. rosbridge 연결 (브라우저 → /task/start)

`web_stt_firebase_v2/src/lib/voice/rosbridge.ts`:

- `roslib` (npm package, ESM 빌드. `@types/roslib`는 `export = ROSLIB` 형태라
  `verbatimModuleSyntax: true` 와 충돌해서 dependency에서 제외, named import만 사용)
- 단일 connection을 모듈 스코프에 캐시; 같은 URL 재사용 시 새로 안 만든다
- `Service<TriggerRequest, TriggerResponse>("/task/start")` 호출, 5초 타임아웃
- `success=False` 응답이거나 timeout이면 `console.warn` 으로 표시만 하고 throw 안 함
  (음성 추천 자체는 이미 Firestore에 publish됐으므로 사용자에게는 결과를 보여주고 싶다)

orchestrator에는 `onDispatch?: (order) => Promise<void>` 훅으로 연결되어 있고,
`useVoiceOrchestrator`가 `VITE_ROSBRIDGE_URL`이 세팅된 경우에만 dispatch 콜백을 등록한다.
이는 Python `run_recommendation_flow(dispatch_callback=...)`의 동작과 동일.

## 7. 디버깅 중 발견한 함정

1. **`colcon build --symlink-install`을 기존 non-symlink 빌드 위에 적용**하면
   `task_manager_node`의 entry_point 메타데이터가 깨져 `PackageNotFoundError:
   No package metadata was found for cobot-task-manager`가 뜬다.
   해결: `rm -rf build/cobot_task_manager install/cobot_task_manager` 후 재빌드
   (이번엔 symlink 없이).

2. **alias 변경 후 새 셸을 안 열면** 기존 셸은 바뀌기 전 alias를 그대로 쓴다.
   bringup이 `FileOrderProvider reading ...latest_order.json` 로그를 찍으면
   alias 갱신 누락 신호. `source ~/.bashrc` 또는 새 터미널.

3. **roslib 타입 충돌**: `@types/roslib`는 legacy `export = ROSLIB; export as
   namespace ROSLIB;` 형태라 `verbatimModuleSyntax: true` (TS 6) 환경에서
   임포트가 깨진다. `@types/roslib`를 떼고 roslib 자체에 포함된 ESM `.d.ts`를
   쓰면 named import (`import { Ros, Service } from "roslib"`)로 깔끔히 동작.

4. **Web Audio capture format**: Whisper API는 webm/ogg/mp3/m4a/wav를 모두 받는다.
   16kHz mono int16 PCM (Python에서 sounddevice + scipy.io.wavfile)을 그대로
   재현하지 않고 `MediaRecorder` 기본 webm/opus를 그대로 보낸다 — 라이브러리
   추가 0, 정확도 차이 미미.

## 8. 운영 절차 (T3 bringup)

1. (1회만) `sudo apt install ros-humble-rosbridge-suite`
2. 터미널 A: `ros2 launch rosbridge_server rosbridge_websocket_launch.xml`
3. 터미널 B: `bringup` (수정된 alias — Firestore source + FIREBASE_SERVICE_ACCOUNT)
4. 터미널 C: `cd ~/cobot_ws/src/cobot2/web_stt_firebase_v2 && npm run dev`
5. 브라우저 (Chrome/Edge): http://localhost:5173 → Start Voice → "hello rokey" / "샤갈"

성공 시 화면 상태 전환: `idle → wake_detected → asking_state → listening_state →
asking_intensity → listening_intensity → recommending → result_ready →
dispatching → completed`. bringup 로그에서 `[task_manager] [state] picking ...`
이 떠야 정상.

## 9. 알려진 한계 / 다음 단계

- **API 키가 브라우저 번들에 노출**됨 (Vite env vars). 데모/로컬에서만 안전.
  운영 배포 시 OpenAI/ElevenLabs 호출을 가리는 작은 serverless proxy 필요.
- **Wake word는 Web Speech API**로 대체 — Chrome/Edge 외 미지원, 정확도/지연이
  openwakeword TFLite 모델보다 낮을 가능성. 다음 단계로 Porcupine Web SDK
  또는 TFJS-tflite 포팅 검토.
- v1 (`web_stt_firebase`)와 v2가 같은 Firestore 문서를 쓰므로 **동시 실행은 충돌**
  (둘 다 `robot_session/current`를 reset/write). 한 번에 하나만 쓰는 것을 전제.
- task_manager의 `order_source` 전환은 `bringup` alias 한 줄로 완결되지만,
  `voice` alias (Python 흐름)는 여전히 `latest_order.json`을 쓰므로 **두 흐름을
  같은 세션에서 번갈아 돌리면 dedup 키가 분리**된다 (FileOrderProvider는 자기
  `_last_request_id`만 추적). 의도된 동작이지만 인지하고 있어야 함.
