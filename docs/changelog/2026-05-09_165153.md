## 1. 배경 (Why)

너트가 서로 가까이 모여 있는 경우, 단일 픽 동작 중 그리퍼 finger가 인접
너트를 튕겨 의도치 않게 이동/이탈시키는 문제가 있었다. 설계 문서 05의
"closed-gripper push로 분산 → 재관측 → 정상 픽" 흐름을 구현해 적용.

## 3. 설계 결정 (Why this shape)

### 3.1 별도 액션 메시지 대신 sentinel target_class 재사용

새 `.action` 정의를 추가하면 `cobot_msgs` 패키지 빌드(C++/Python 인터페이스
재생성)가 필요하고, action client/server 양쪽에 새 타입을 묶어야 한다.
대신 **`PickAndPlace` 액션을 그대로 쓰면서 `target_class == "__cluster_push__"`**
sentinel일 때 의미를 재해석:

| 필드 | pick 의미 | cluster push 의미 |
|---|---|---|
| `grasp_xyz` | 그립 위치 | 진입점 (descend 좌표) |
| `grasp_yaw` | 그립 yaw | push 방향 yaw (`atan2(dy, dx)`) |
| `pre_grasp_width_mm` | pre-position 폭 | 0 (닫힌 채 진입) |
| `return_xyz` | 컨베이어 place | push 종점 |
| `return_zyz_deg` | place orientation | (사용 안 함) |

sentinel 문자열은 `task_manager_node.py`와 `robot_control_node.py`에
**동일 상수 `CLUSTER_PUSH_TARGET_CLASS = "__cluster_push__"`** 로 박아두고,
한쪽 변경 시 같이 갱신해야 한다는 주석을 양쪽에 남김.

### 3.2 cluster_policy를 별도 모듈로 분리

기하 계산(이웃 탐색, 수직축, 후보 좌표, BBox 충돌, workspace 체크)을
`task_manager_node`에서 분리해 단위 테스트가 가능하도록 함. 같은 사유로
`target_selector.py`도 별도 모듈인 패턴을 따름.

### 3.3 push z = grasp z + offset (per-class 보정 분리)

처음 구현 시 push z를 단순히 `target.base_xyz.z`로 두었는데, grasp z는
`base_z + per_class_z_offset` (예: cashew=-2mm)이 적용되어 있어 둘이
일치하지 않는 문제가 발생. 사용자 의도("grasp보다 살짝 위에서 밀기")를
반영해 다음 식을 채택:

```
push_z = base_z + per_class_z_offset + cluster_push_z_offset_mm
```

`task_manager_node`에서 두 보정을 합쳐 `cluster_policy.choose_cluster_plan`
의 `push_z_offset_mm`로 전달. 결과적으로 클래스별 grasp 깊이를 그대로
존중하면서 push만 일률적으로 +2mm 띄움.

## 4. 파일별 변경 상세

### 4.1 신규: `cobot_task_manager/cobot_task_manager/cluster_policy.py`

`choose_cluster_plan(...)` — `(detections, target, workspace, *, cluster_dist_threshold_mm,
candidate_offset_mm=10, push_scale=1.5, push_z_offset_mm=0, conf_gate, min_depth_mm)`
→ `Optional[ClusterPlan]`.

알고리즘:
1. **유효 detection 필터** — target 자신 제외, conf_gate / transform_valid /
   min_depth / workspace 게이트.
2. **최근접 이웃 탐색** — 직선거리 최소 (xy 평면).
3. **군집 판정** — `dist < cluster_dist_threshold_mm` 이고 `dist >= 1e-6`
   (dedup 미스 케이스 제외).
4. **수직축 산출** — target→neighbor 직선의 단위 perpendicular vector.
   `ax = -(ny-ty)/dist, ay = (nx-tx)/dist`.
5. **두 후보 진입점** — `target ± candidate_offset_mm × (ax, ay)`.
6. **선정 우선순위** — (1) 다른 BBox 충돌 없는 후보, (2) y 큰 쪽.
   둘 다 차단되면 None 반환 (호출측이 일반 pick으로 fallback).
7. **푸시 종점** — `target - push_scale × (entry - target)`. `push_scale=1.5`
   에서 진입 변화량의 1.5배만큼 반대 방향으로 푸시.
8. **workspace 재확인** — 진입점, 푸시 종점 모두 z 보정 적용 후 안에 있을 것.

OBB 충돌 검사는 `_point_in_oriented_box`에서 yaw로 회전한 local frame
좌표가 `[-long/2, +long/2] × [-short/2, +short/2]` 안인지 확인.

### 4.3 `task_manager_node.py`

#### import + sentinel
```python
from .cluster_policy import choose_cluster_plan

CLUSTER_PUSH_TARGET_CLASS = "__cluster_push__"
```

#### 파라미터 declare
```python
self.declare_parameter("cluster_enabled", True)
self.declare_parameter("cluster_dist_threshold_mm", 35.0)
self.declare_parameter("cluster_candidate_offset_mm", 10.0)
self.declare_parameter("cluster_push_scale", 1.5)
self.declare_parameter("cluster_push_z_offset_mm", 2.0)
self.declare_parameter("max_cluster_pushes_per_class", 2)
```

#### 사이클별 카운터 (`_run` 시작)
```python
self._cluster_push_counts: Dict[str, int] = {}
```
이전 사이클 상태가 누적되어 새 주문에서 push가 차단되는 것 방지.

#### `_send_cluster_push_goal(plan)` 헬퍼
ClusterPlan을 PickAndPlace.Goal로 변환:
- `target_class = CLUSTER_PUSH_TARGET_CLASS` (sentinel)
- `grasp_xyz` ← `plan.entry_xyz_mm`
- `grasp_yaw` ← `atan2(dy, dx)` (entry→push_end 방향)
- `pre_grasp_width_mm = 0` (닫힌 채 진입; 액션 서버가 pre-position 단계 skip)
- `return_xyz` ← `plan.push_end_xyz_mm`

`_send_pick_goal`과 동일한 wait_for_server / send_goal_async / get_result_async
패턴.

#### `_process_order_book` 내 cluster 분기 (PICK_AND_PLACE 직전)
```python
if (
    self._cluster_enabled
    and self._cluster_push_counts.get(target_class, 0)
        < self._max_cluster_pushes_per_class
):
    push_z_total_offset = (
        self._per_class_z_offset_mm.get(target_class, 0.0)
        + self._cluster_push_z_offset_mm
    )
    cluster_plan = choose_cluster_plan(
        objects_msg.objects, candidate, self._workspace,
        cluster_dist_threshold_mm=self._cluster_dist_threshold_mm,
        candidate_offset_mm=self._cluster_candidate_offset_mm,
        push_scale=self._cluster_push_scale,
        push_z_offset_mm=push_z_total_offset,
        conf_gate=self._conf_gate,
        min_depth_mm=self._min_depth_mm,
    )
    if cluster_plan is not None:
        self._cluster_push_counts[target_class] = ... + 1
        self._set_state(TaskState.CLUSTER_PUSH, ...)
        push_result = self._send_cluster_push_goal(cluster_plan)
        if push_result is None:           # 인프라 실패 → ABORT
            ...
        if not push_result.success:       # motion 실패 → 일반 pick으로 fallthrough
            ...
        else:                             # 성공 → settle → 재관측
            time.sleep(self._inter_pick_delay_sec)
            continue
```

핵심:
- `continue`로 detect 사이클 처음으로 돌아가 **재관측 후 다시 후보 선정**
- `cluster_push_counts` 상한 초과 시 cluster 분기 skip → 일반 pick fallback
- push 자체 실패(action 서버 미가용)는 ABORT, push motion 실패는 fallthrough

### 4.4 `task_manager.yaml`

```yaml
# Cluster handling — closed-gripper push to disperse adjacent nuts.
cluster_enabled: true
cluster_dist_threshold_mm: 30.0
cluster_candidate_offset_mm: 25.0
cluster_push_scale: 1.5
cluster_push_z_offset_mm: 2.0
max_cluster_pushes_per_class: 2
```

> **빈도 보장**: cluster check는 `_process_order_book`의 매 루프 반복마다
> 실행된다 (detect → choose_target → cluster check → push or pick).
> 즉 **모든 픽 시도마다** 그 시점의 detection으로 군집 여부를 새로
> 판정하므로, "처음 한 번만 검사" 같은 게이팅은 없다. 단 같은 클래스의
> push 횟수는 `max_cluster_pushes_per_class`로 cap.

### 4.5 `motion_sequence.py` — `execute_closed_gripper_push(...)`

```python
def execute_closed_gripper_push(
    motion, gripper, cfg,
    entry_xyz_mm, push_end_xyz_mm,
    push_yaw_rad=0.0,
    feedback_cb=None, is_cancelled=None,
):
```

Stage sequence:
1. `close_gripper` — 닫고 settle 대기
2. `approach` — entry 위 `approach_offset_z_mm` 지점 (line move)
3. `descend` — entry z (slow speed)
4. `push` — push_end로 직선 (slow speed; 빠르면 너트가 튕겨 나감)
5. `retreat` — push_end 위 approach 높이
6. `home` — joint move
7. (마무리) `gripper.open()` — 다음 사이클 시작 시 의외의 큰 width 이동
   방지

failure_code는 `execute_pick_and_place`와 동일 매핑 (3=motion, 4=cancel,
5=workspace). grasp 관련 코드(1, 2)는 push에 적용 안 됨.

## 5. 단위 검증 (실기 전)

`cluster_policy.choose_cluster_plan`을 합성 detection으로 직접 호출:

| 케이스 | 입력 | 기대 |
|---|---|---|
| 1. 군집 (dist=5mm) | target (400,0), neighbor (400,5), 다른 너트 멀리 | plan 반환, entry 두 후보 중 BBox-clear & y 큰 쪽 |
| 2. 비군집 (dist > threshold) | target (400,0), neighbor (500,100) | None |
| 3. BBox 차단 | 케이스 1 + 한쪽 후보 좌표에 다른 너트 OBB | 반대쪽 후보 선정 |

세 케이스 모두 의도대로 동작. 테스트 코드는 conversation 기록에만 남기고
별도 파일로는 커밋하지 않음.

## 6. 실기 튜닝 기록

세션 중 사용자가 직접 yaml 값을 다음 순서로 조정:

| 순번 | `cluster_dist_threshold_mm` | `cluster_candidate_offset_mm` | 비고 |
|---|---|---|---|
| 초기 | 35.0 | 10.0 | 첫 구현 |
| 1차 | 3.0 | 20.0 | 거의 발동 안 됨 — 너트 중심 거리는 보통 ≥ 12mm |
| 2차 | 25.0 | 15.0 | 정상 발동 시작 |
| 3차 | 25.0 | 25.0 | 진입점이 너트 OBB 안에 자주 들어오는 문제 → offset 키워 회피 |
| **최종** | **30.0** | **25.0** | 실기에서 닿아 있는 두 번째 너트 페어 일부가 25mm 직전에 머물러 미발동 — 임계값 5mm 상향 |

또 push 동작 검증 중 "push z가 grasp z와 어긋나 보임"이 보고돼,
`cluster_push_z_offset_mm = 2.0` 신설 + per-class offset과 합쳐 전달하는
구조로 변경 (3.3절 참조).

**최종 실기 결과**: 군집 너트 정상 분산 + 재관측 → 정상 픽까지 사이클 성공.
사용자 검증 패스 (2026-05-09 17:00경).

### 6.1 디버그 에피소드 — install/src yaml 동기화 누락

세션 중 사용자가 "push가 아예 안 걸린다"고 보고한 시점, src yaml은
`dist_threshold=25, offset=15`였으나 install 사본은 직전 튜닝값 `3, 20`이
그대로 남아 있었다 (사용자가 IDE에서 src를 바로 수정했지만 install로의
cp가 그 사이 누락됨). 노드는 install/share의 yaml을 launch 시점에 읽으므로
**임계값 3mm로 동작 → 사실상 군집 분기가 절대 안 걸리는 상태**였음.

#### 교훈
- `cobot_task_manager`는 install이 site-packages **사본** 구조라 src 편집
  후 매번 `cp` 필요. (반면 `cobot_robot_control`은 egg-link로 src 직참조,
  `cobot_config/pick_offsets.yaml`은 install→src 심링크 — 이 둘은 cp 불필요.)
- 향후 같은 사고 방지를 위해, yaml 변경 시 항상 src/install diff 한 번
  찍고 작업 종료. 또는 `cobot_task_manager`의 setup.py를
  `--symlink-install` 친화 구조로 바꾸는 것도 고려 가능 (현재는 cp 기반
  install이라 symlink-install로 빌드해도 yaml은 사본).

## 7. 빌드/배포

- 새 모듈 `cluster_policy.py`는 entry point 아님 → `setup.py`/`egg-info` 갱신
  불필요.
- `cobot_robot_control` install이 egg-link이고 build dir은 src 심링크 →
  src 수정 즉시 반영.
- `cobot_task_manager`는 install이 site-packages 사본 → src→install 수동 cp.
- `pick_offsets.yaml`은 install/share에서 src로의 심링크.

따라서 **colcon build 없이 src 편집 + (task_manager 한정) install 동기화 +
노드 재시작**만으로 적용 가능. 본 세션에서는 cp만 사용.

## 8. 남은 과제 (Open)

설계 문서 05의 "추후 검토 사항" 중 일부:
- 푸시 후에도 군집이 유지되는 케이스 한도 (`max_cluster_pushes_per_class=2`로
  잠정 cap; 실기에서 충분한지 추가 관찰 필요)
- 두 후보 좌표 모두 BBox 안일 때 fallback (현재는 None → 일반 pick으로
  fallthrough; 실패 시 verification 라운드가 보충)
- `cluster_dist_threshold_mm`을 OBB 간 gap 기준으로 바꿀지 (현재는 중심 간
  거리). 중심 거리는 너트 크기에 따라 의미가 달라져 임계값을 클래스별로
  분리해야 할 수도 있음. 실기 튜닝에서 30mm가 최종이지만 이건 거의
  "닿아 있는 두 너트의 중심 거리 ≈ long_axis"에 맞춘 휴리스틱.
- 사이클 종료 시 `_cluster_push_counts`가 리셋되는 시점이 `_run` 시작
  뿐이라, verification 라운드는 같은 사이클로 묶여 cap이 누적된다.
  verification 라운드를 새 사이클로 셀지는 향후 정책 결정 필요.
