## 2. 상세 기술적 이슈 분석 및 해결

### 2.1. 브라우저 보안 정책에 따른 CORS 에러
- **문제 현황**: Vite 개발 서버(`:5173`)에서 작동하는 React 앱이 Python API 서버(`:8000`)에 데이터를 요청할 때 브라우저의 동일 출처 정책(SOP)에 의해 요청이 차단됨.
- **해결 방안**: `db_server.py`의 `do_GET` 및 `do_OPTIONS` 메소드에 `Access-Control-Allow-Origin: *` 헤더를 추가하여 모든 출처로부터의 요청을 허용하도록 설정. 또한 브라우저의 사전 요청(Preflight) 처리를 위해 `OPTIONS` 메소드 대응 로직을 추가함.

### 2.2. 복합 UI 요소의 수직 길이 오버플로우
- **문제 현황**: 기존 LOKI 대시보드 하단에 도감 박스를 배치했을 때, 상세 정보의 양이 많아 화면 하단 밖으로 UI가 잘리는 현상 발생.
- **해결 방안**: 
    - **버튼 레이아웃**: 수직 나열 방식에서 **1x4 가로 그리드** 방식으로 변경.
    - **상세 정보**: 단순 수직 나열에서 **2x2 카드 그리드** 방식으로 변경하여 수직 높이를 약 50% 절감.
    - **컴포넌트 경량화**: `padding`과 `font-size`를 유동적으로 축소하여 가독성을 유지하면서 전체 높이를 최적화함.

### 2.3. 박스 모델 차이로 인한 가로 너비 불일치
- **문제 현황**: 상단 상태 바 박스와 하단 도감 박스의 가로 시작/끝 점이 미세하게(수 픽셀 단위) 어긋나는 현상 발생.
- **원인 분석**: 브라우저 기본값인 `content-box`와 수동으로 설정한 `maxWidth`가 섞여 있어, 패딩값이 박스 너비 계산에 제각각 영향을 줌.
- **해결 방안**: 
    - 상하단 박스 모두에 `box-sizing: border-box`를 명시적으로 선언.
    - `maxWidth` 대신 고정 너비인 `width: 440px`를 공통 적용하여 해상도와 관계없이 일관된 레이아웃을 보장함.

### 2.4. 다국어(한글) 검색 파라미터 처리 오류
- **문제 현황**: '아몬드', '피스타치오' 등 한글 이름을 쿼리 파라미터로 보낼 때 API 서버에서 인코딩 문제로 데이터를 찾지 못하는(404) 사례 발생.
- **해결 방안**: 
    - **Frontend**: `fetch` 요청 시 `encodeURIComponent(name)`를 사용하여 안전하게 URL 인코딩 처리.
    - **Backend**: `urllib.parse.parse_qs`를 사용하여 디코딩된 데이터를 수신하고, SQL 쿼리 시 바인딩 파라미터(`?`)를 사용하여 인젝션 방지 및 정확한 문자열 매칭 구현.

## 3. 향후 유지보수 제언
- **데이터 확장성**: 현재는 4종의 견과류만 지원하나, `init_db.py`에 데이터를 추가하는 것만으로 즉시 확장이 가능함.
- **서버 통합**: 현재는 별도의 Python 서버(`db_server.py`)를 사용 중이나, 추후 전체 시스템 통합 시 Flask나 FastAPI 같은 전문 웹 프레임워크로 전환하여 보안 및 관리 효율성을 높일 수 있음.
