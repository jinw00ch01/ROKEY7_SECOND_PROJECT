# 군집 견과류 처리 기능 (Clustered Nuts Handling)

## 1. 문제 인식 (Problem Statement)

잡아야 하는 견과류가 서로 가까이 모여 있는 경우, 하나의 객체를 집기 위해 그리퍼를 하강시키면 인접한 다른 견과류가 그리퍼에 튕겨 나가는 문제가 발생한다.

- **증상**: 단일 픽 동작 중 인접 객체가 의도치 않게 이동/이탈
- **원인**: 그리퍼 폭 + 하강 경로 내에 다수의 견과류가 동시에 존재
- **영향**: 픽 실패율 증가, 작업 영역 외부로 객체 이탈 가능성

## 2. 해결 방안 개요 (Solution Overview)

군집 상태로 판단되는 견과류는 **밀어내기 동작(push-apart)** 으로 군집을 분산시킨 후, 다시 관측 단계부터 본 작업을 재시작한다.

> **핵심 아이디어**
> 두 견과류를 한 번에 같이 밀어내면 안 되므로, 그리퍼 이동 방향이 **바운딩 박스 하나에만 겹치도록** 해야 효율적이다.
> 이를 위해 두 바운딩 박스가 겹쳐서 생긴 변을 확장한 **축을 기준**으로 한쪽 방향으로만 이동한다.

## 3. 상세 절차 (Detailed Procedure)

### 3.1 군집 판정 (Cluster Detection)

- 관측(observation) 시점에 대상 견과류와 **다른 견과류 중심점 간의 거리**를 계산
- 거리가 **임계값 미만**이면 군집 상태로 판정
- 군집 판정 시: **그리퍼를 닫은 채로** 다음 분산(push-apart) 동작으로 진입
  - (그리퍼를 닫는 이유: 하강/이동 중 그리퍼 사이로 객체가 끼는 것을 방지)

### 3.2 후보 좌표 생성 (Candidate Pose Generation)

대상 견과류의 위치를 기준으로, **특정 축과 평행한 방향**으로 **거리 10만큼 떨어진 2개의 좌표**를 생성한다.

```
                  candidate_A (+축 방향, 거리 10)
                      │
                  ────●────  ← 대상 견과류
                      │
                  candidate_B (-축 방향, 거리 10)
```

각 후보 좌표 위치에 **다른 견과류의 바운딩 박스가 존재하는지 검사**한다.

### 3.3 후보 선정 우선순위 (Selection Priority)

두 후보 좌표 중 다음 우선순위로 진입 좌표를 선택한다.

| 우선순위 | 조건 |
| :---: | :--- |
| 1순위 | **다른 견과류의 바운딩 박스가 없는** 좌표 |
| 2순위 | **y 값이 큰** 좌표 |

선정된 좌표로 이동한 뒤 **하강(descend)** 한다.

### 3.4 밀어내기 동작 (Push-Apart Motion)

진입 시 발생한 **Δx, Δy(=10 기준 변화량)** 의 **1.5배를 반대 방향**으로 이동시켜, 대상 견과류를 군집 밖으로 밀어낸다.

```
이동량 = (-1.5 · Δx, -1.5 · Δy)
```

- 이로써 대상 견과류 한 개만 군집에서 분리
- 인접 객체는 그리퍼 경로 밖에 있으므로 영향 최소화

### 3.5 재시작 (Restart Cycle)

밀어내기 동작 완료 후:

1. 로봇을 **홈 자세(home pose)** 로 복귀
2. 본 작업 흐름의 **관측 단계부터 재시작**
3. 다시 군집 판정 → 분산 또는 정상 픽 분기

## 4. 동작 흐름 다이어그램 (Flow)

```
[관측(Observe)]
      │
      ▼
[중심점 거리 계산]
      │
   거리 < 임계값 ?
   ┌──┴──┐
  YES    NO
   │      │
   │      └──▶ [정상 Pick 진행]
   │
   ▼
[그리퍼 닫기]
      │
      ▼
[2개 후보 좌표 생성 (특정 축 평행, 거리 10)]
      │
      ▼
[각 후보 위치 BBox 검사]
      │
      ▼
[우선순위 적용]
  1) BBox 없는 쪽
  2) y 큰 쪽
      │
      ▼
[선정 좌표로 이동 → 하강]
      │
      ▼
[(Δx, Δy) × -1.5 만큼 이동 → 대상 푸시]
      │
      ▼
[Home 복귀]
      │
      ▼
[관측 단계로 재진입]
```

---

## 5. 파라미터 정리 (Parameters)

| 이름 | 의미 | 비고 |
| :--- | :--- | :--- |
| `cluster_dist_threshold` | 군집 판정 거리 임계값 | 중심점 간 거리 기준 |
| `candidate_offset` | 후보 좌표 오프셋 (= 10) | 특정 축 평행 거리 |
| `push_scale` | 푸시 이동 배율 (= 1.5) | 진입 변화량의 반대 방향 배수 |
| `cluster_axis` | 후보 좌표 생성 축 | 두 BBox 겹침 변을 확장한 축 |

---

## 6. 추후 검토 사항 (Open Questions)

- `cluster_dist_threshold` 와 `candidate_offset` 의 단위 (픽셀 / mm) 및 캘리브레이션 기준
- `cluster_axis` 산출 방식 — 두 BBox 겹침 변 추출 알고리즘 명세 필요
- 후보 좌표 모두 BBox와 충돌하는 경우의 fallback 정책
- 푸시 이후에도 군집이 유지될 때의 재시도 횟수 제한
- 그리퍼 닫힘 상태에서의 충돌 회피 / 안전 영역 검사 필요 여부
